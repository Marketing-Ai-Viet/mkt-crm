## Breaking Changes v3.0

| Change | Details |
|--------|---------|
| `departmentCode` removed from input | Client **KHÔNG CẦN** truyền `departmentCode` khi tạo/cập nhật |
| `departmentCode` removed from output | Response **KHÔNG TRẢ VỀ** `departmentCode` |
| Auto-generation | Backend tự động tạo `departmentCode` từ `departmentName` |

### Migration Guide (v2.x -> v3.0)

**Before (v2.x):**
```graphql
mutation {
  createDepartment(input: {
    departmentCode: "SALES-001"  # Required in v2.x
    departmentName: "Sales"
  }) {
    department {
      departmentCode  # Available in v2.x
    }
  }
}
```

**After (v3.0):**
```graphql
mutation {
  createDepartment(input: {
    # departmentCode removed - auto-generated by backend
    departmentName: "Sales"
  }) {
    department {
      id              # Use id instead
      departmentName
      # departmentCode not available
    }
  }
}
```

## 1. Overview

Department CRUD Resolver cung cấp các API GraphQL để quản lý phòng ban (Department) trong hệ thống CRM. Resolver này thay thế các auto-generated mutations của Twenty CRM để đảm bảo business logic được kiểm soát chặt chẽ.

### Tính năng chính
- **Query**: Lấy thông tin department theo ID hoặc code
- **Create**: Tạo mới department (departmentCode auto-generated)
- **Update**: Cập nhật department
- **Delete**: Xóa mềm (soft delete) department
- **Sub-Manager Management**: Quản lý sub-managers của department

### Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                    GraphQL Request                          │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│              WorkspaceAuthGuard + UserAuthGuard             │
│                   (Authentication Layer)                    │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                  DepartmentCrudResolver                     │
│         (GraphQL Resolver - Request/Response handling)      │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                   DepartmentCrudService                     │
│        (Business Logic + Auto-generate departmentCode)      │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                  MktDepartmentRepository                    │
│                    (Data Access Layer)                      │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                       PostgreSQL                            │
│                 (mktDepartment table)                       │
└─────────────────────────────────────────────────────────────┘
```

## 2. Authentication

### Required Headers

```http
Authorization: Bearer <access_token>
Content-Type: application/json
```

### Guards Applied
- `WorkspaceAuthGuard`: Xác thực workspace context
- `UserAuthGuard`: Xác thực user trong workspace

### Token Structure (JWT Payload)
```json
{
  "sub": "<user-id>",
  "userId": "<user-id>",
  "workspaceId": "<workspace-id>",
  "workspaceMemberId": "<workspace-member-id>",
  "type": "ACCESS",
  "authProvider": "password",
  "iat": 1769422459,
  "exp": 1777198459
}
```

### Error Responses

| Status | Code | Message |
|--------|------|---------|
| 401 | `UNAUTHENTICATED` | No token provided |
| 401 | `UNAUTHENTICATED` | Invalid or expired token |
| 403 | `FORBIDDEN` | Workspace access denied |

## 7. Error Handling

### Error Response Structure

Tất cả mutations trả về response có cấu trúc nhất quán:

```typescript
{
  success: boolean;      // true nếu thành công
  department?: object;   // Dữ liệu department (nếu thành công)
  subManagers?: array;   // Sub-managers (nếu có)
  deletedId?: string;    // ID đã xóa (chỉ cho delete)
  error?: string;        // Thông báo lỗi (nếu thất bại)
}
```

### Error Types

| Error | Cause | Response |
|-------|-------|----------|
| `Department not found: {id}` | ID không tồn tại hoặc đã bị xóa | `success: false` |
| `invalid input value for enum` | Giá trị enum không hợp lệ | `success: false` |
| `UNAUTHENTICATED` | Token không hợp lệ | GraphQL error |
| `FORBIDDEN` | Không có quyền truy cập workspace | GraphQL error |

### Enum Values

**departmentType:**
- `"DEPARTMENT"` - Phòng ban
- `"TEAM"` - Nhóm/Đội

### Notes
- **Soft Delete**: Khi xóa department, record vẫn tồn tại trong database với `deletedAt` được set. Các query sẽ không trả về record đã xóa.
- **departmentCode Auto-generation**: Backend tự động tạo từ `departmentName` theo format: `{kebab-case-name}-{8-char-uuid}`. VD: "Phòng Kinh Doanh" → "phong-kinh-doanh-a1b2c3d4"

## 8. Usage Examples

### 8.1 cURL Examples

**Query - Get by ID:**
```bash
curl -X POST http://localhost:3000/graphql \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-token>" \
  -d '{
    "query": "query { getDepartmentById(id: \"ad95f81e-bda5-4a98-b72a-880c0b5c204c\") { id departmentName departmentType isActive } }"
  }'
```

**Mutation - Create (Minimal):**
```bash
curl -X POST http://localhost:3000/graphql \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-token>" \
  -d '{
    "query": "mutation { createDepartment(input: { departmentName: \"New Department\" }) { success department { id departmentName } error } }"
  }'
```

**Mutation - Create (With Sub-Managers):**
```bash
curl -X POST http://localhost:3000/graphql \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-token>" \
  -d '{
    "query": "mutation { createDepartment(input: { departmentName: \"Sales Team\", departmentType: \"TEAM\", subManagers: [{ workspaceMemberId: \"member-uuid\", isPrimary: true }] }) { success department { id } subManagers { id isPrimary } error } }"

  subManagers?: SubManagerOutput[];
  error?: string;
};

type DeleteDepartmentResponse = {
  success: boolean;
  deletedId?: string;
  error?: string;
};
```

## 9. Best Practices

### 9.1 Department Types

| Type | Description | Use Case |
|------|-------------|----------|
| `DEPARTMENT` | Phòng ban chính | SALES, HR, ACCOUNTING |
| `TEAM` | Đội nhỏ trong phòng ban | SALES_DOMESTIC, TECH_BACKEND |

### 9.2 Hierarchy Recommendation

```
DEPARTMENT (Level 1)
└── TEAM (Level 2)
    └── TEAM (Level 3) - nếu cần

Ví dụ:
SALES (DEPARTMENT)
├── SALES_DOMESTIC (TEAM)
├── SALES_INTERNATIONAL (TEAM)
└── SALES_ONLINE (TEAM)
```

### 9.3 Error Handling Best Practice

```typescript
const result = await createDepartment.mutateAsync(input);

// Luôn kiểm tra success trước
if (!result.success) {
  const error = result.error || 'Unknown error';

  if (error.includes('not found')) {
    showError('Phòng ban không tồn tại');
  } else if (error.includes('invalid input value for enum')) {
    showError('Giá trị không hợp lệ');
  } else {
    showError(error);
  }
  return;
}

// Process success case
const department = result.department;
```

### 9.4 Manager Assignment

- `managerId` phải là UUID của `workspaceMember` trong cùng workspace
- Một department có thể không có manager (managerId = null)
- Manager có thể quản lý nhiều department
